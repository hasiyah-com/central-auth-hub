## ทำอะไรบ้าง (รอบนี้)

### 1. Fix — ML/RBA ไม่รันบน Hub-direct passkey login
- **อาการ:** Session Detail ของ Hub (login ด้วย passkey) โชว์ `risk_score 0.000` เสมอ — ML ไม่เคยรัน
- **สาเหตุ:** `login_finish` / `discoverable_finish` hardcode `risk_score=0.0` ตอนสร้าง `LoginSession`
- **แก้:** เพิ่ม helper `_build_login_session(result, request, jti, db, method)` ใน `routers/passkey.py`
  รัน 4-Layer RBA เต็ม:
  `extract_session_features` → `evaluate_login_risk` → counter-regression boost (+0.2)
  → `maybe_alert_ml_risk` → เขียน `LoginSession` ด้วย risk/anomaly/decision/reasons จริง
  - passkey = strong auth → block แปลงเป็น `would_block` (ไม่บล็อก login จริง)
  - wire เข้าทั้ง `login_finish` + `discoverable_finish`
- **Verify:** risk_score 0.000 → 0.4, anomaly 0.49, decision `would_warn`, reasons เต็ม ✅

### 2. IP `::ffff:172.18.0.1` — อธิบาย + normalize
- **ไม่ใช่บั๊ก** — เป็น dev artifact: passkey login เข้าผ่าน proxy 2 hop
  (browser → Next container → backend) → dev ไม่มี `X-Forwarded-For` →
  backend เห็น docker bridge gateway `172.18.0.1` (รูป IPv4-mapped IPv6)
- ยืนยัน proxy forward XFF ถูก: ส่ง `X-Forwarded-For: 203.0.113.55` → backend บันทึก `203.0.113.55` จริง
  → prod (หลัง nginx) จะได้ public IP จริง
- **ปรับ:** `_valid_ip_or_none()` ใน `deps.py` normalize IPv4-mapped IPv6
  (`::ffff:172.18.0.1` → `172.18.0.1`) — geo/ML ทำงานกับ IPv4 ตรงๆ + dashboard อ่านง่าย
  - `::1` (IPv6 จริง) คงไว้, `garbage` → None (กัน INET crash/DoS เหมือนเดิม)
