# ผลทดลอง L3 Auth Context — 3 ตุลาคม 2026

**ข้อมูลจำลองเท่านั้น — ยังไม่ใช่หลักฐานประสิทธิภาพ production และไม่มีการเปิดใช้งานโมเดลใหม่**

ทดลอง 22 แบบ: เดิม 23 ฟีเจอร์, เพิ่มทีละ 4 กลุ่ม, เพิ่มทั้งหมด 38, เฉพาะใหม่ 15 และเพิ่มทีละพารามิเตอร์ 15 แบบ ใช้ข้อมูลและ user holdout เดียวกัน seed 42 โดยฝึก Isolation Forest 100 trees / max_samples 256 ด้วยข้อมูลปกติเท่านั้น

## ชุดข้อมูลและเกณฑ์

- 300 บัญชีจำลอง บัญชีละ 40 เหตุการณ์ปกติและ 8 สถานการณ์โจมตี รวม 14,400 เหตุการณ์; สัดส่วนโจมตี 16.67% เป็นค่าจำลอง
- แยกบัญชี 180/60/60 สำหรับ train/calibration/test ไม่มีบัญชีซ้ำข้ามชุด; test มีปกติ 2,400 และโจมตี 480
- ปกติมีการกู้บัญชี เปลี่ยนอุปกรณ์ authenticator และเปลี่ยนภาษาบางส่วน เพื่อไม่ถือว่าการเปลี่ยนแปลงทุกครั้งเป็นโจมตี
- เกณฑ์ warn = percentile 99 ของคะแนนปกติ calibration; challenge จำลอง = percentile 99.9; แจ้งเตือนเมื่อคะแนนมากกว่าเกณฑ์ ไม่ปรับเกณฑ์จาก test
- รอบนี้ใช้เกณฑ์รวมเพื่อแยกผลของฟีเจอร์ ยังไม่ได้ทดสอบเกณฑ์แยกประเภทผู้ใช้ จึงไม่ใช่การประเมินนโยบาย production ทั้งระบบ
- PR-AP คือ Average Precision; ไม่ใช่พื้นที่ PR แบบ trapezoid และไม่สามารถแปลเป็น precision ของระบบจริงจากสัดส่วนโจมตีจำลองนี้

## ข้อค้นพบและขอบเขต

โมเดลครบ 38 ฟีเจอร์ PR-AP เพิ่มจาก 0.2566 เป็น 0.3045 แต่ recall ที่เกณฑ์ calibration ลดจาก 23/480 เป็น 22/480 และ cold-start FPR เพิ่มจาก 0.5% เป็น 3.0% จึงยังไม่ควรแทนโมเดลเดิม การเพิ่มทุกฟีเจอร์พร้อมกันไม่ได้รับประกันผลดี

Recovery/reset ให้ ROC recall ที่ FPR test ≤1% เพิ่มจาก 5.21% เป็น 8.54% แต่ผลที่เกณฑ์ calibration ส่วนใหญ่ดีขึ้นในตระกูล new_device ไม่ใช่ recovery_takeover จึงยังพิสูจน์ไม่ได้ว่าฟีเจอร์นี้ตรวจ Account Takeover ได้จริง

โมเดลเฉพาะใหม่ตรวจพบหลัง L1–2 allow 35/212 เหตุการณ์ แต่มี test FPR 1.375% และ cold-start FPR 4.5%; ข้อมูลใหม่มีสัญญาณให้ศึกษาต่อ แต่ยังไม่มีหลักฐานเพียงพอให้อำนาจ challenge

L1–2 ใช้โค้ดกฎ/behavior/aggregate จริงกับโปรไฟล์จำลอง ผล recall 55.83%, FPR 31.33% เป็นผลของ fixture นี้เท่านั้น โดยไม่ได้ตรวจ blacklist/IP/ฐานข้อมูลและ provenance ของความล้มเหลวครบเส้นทาง production ห้ามนำตัวเลขนี้ไปอ้างว่าเป็นคุณภาพ L1–2 จริง

ฐาน 23 ฟีเจอร์สุ่มจากแถวปกติของ generator เดิมแบบคืนตัวอย่าง ฟีเจอร์บริบทมาจาก build_context จริง แต่ประวัติและ labels เป็นการสร้างสถานการณ์ ไม่ใช่บัญชีจริง สถานการณ์เปลี่ยนภาษา/วิธีเข้าสู่ระบบมีความทับซ้อนกับพฤติกรรมปกติ และไม่ได้แปลว่าโจมตีเสมอ

พฤติกรรมหลังล็อกอิน 6 ฟีเจอร์ไม่ได้รวมใน 38 ฟีเจอร์และยังไม่ได้วัดประสิทธิภาพในรอบนี้ เพราะเป็นคนละเวลา/หน่วยข้อมูล ต้องใช้ window labels ที่ตรวจสอบแยก ห้ามยืม login labels มาใช้ ส่วน Sequence และขั้นตอนออนไลน์ครบระบบก็ไม่ได้ประเมินในรอบนี้

p95 วัดการให้คะแนนหนึ่งแถวบน CPU อุ่น 100 ครั้ง ไม่รวม DB/Redis/HTTP/สกัดฟีเจอร์ ผลรอบเดียว seed 42 ยังไม่มี confidence interval หรือการทดสอบหลาย seed

ขั้นถัดไปที่มีเหตุผล: ใช้ snapshot จริงที่ติด label, แยก calibration ตามประเภทผู้ใช้และ cold-start, ทดสอบหลาย seed และประเมินการพบเพิ่มบน L1–2 allow จริง ก่อนพิจารณาเปิดใช้งาน
