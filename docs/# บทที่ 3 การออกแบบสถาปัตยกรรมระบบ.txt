# บทที่ 3 การออกแบบสถาปัตยกรรมระบบ (System Architecture Design)

เอกสารนี้ใช้เป็นแนวทางสำหรับออกแบบสถาปัตยกรรมของระบบทั้งหมด โดยจัดลำดับจากภาพรวมของระบบไปจนถึงการติดตั้งจริง เพื่อให้ผู้อ่านสามารถเข้าใจการทำงานของระบบได้อย่างเป็นขั้นตอน และสอดคล้องกับการพัฒนาระบบจริง

---

# 3.1 ภาพรวมสถาปัตยกรรมระบบ (Overall System Architecture)

## วัตถุประสงค์

อธิบายองค์ประกอบทั้งหมดของระบบ และความสัมพันธ์ระหว่าง

- ผู้ใช้งาน
- ระบบย่อย
- ระบบศูนย์กลาง (Hub)
- ระบบ Machine Learning
- ฐานข้อมูล
- Identity Provider

## องค์ประกอบ

### ผู้ใช้งาน (Users)

ประกอบด้วย

- นักศึกษา
- อาจารย์
- เจ้าหน้าที่
- ผู้ดูแลระบบ

---

### ระบบย่อย (Subsystem)

ตัวอย่าง

- ระบบจองห้อง
- ระบบห้องสมุด

Subsystem ไม่มีระบบ Login ของตนเอง

ใช้ Authentication จาก Hub ทั้งหมด

แต่ละระบบจะได้รับ

- client_id
- client_secret
- redirect_uri
- allowed scopes

จาก Hub

---

### Central Authentication Hub

เป็นศูนย์กลางของระบบทั้งหมด

ประกอบด้วย

#### Authentication

- Google OAuth2/OIDC
- Passkey (WebAuthn)

#### Authorization

- RBAC
- Access List

#### Hybrid Risk-Based Access

ประกอบด้วย

- Feature Extraction
- Behavior Analysis
- Isolation Forest
- Passkey Trust Layer
- Score Aggregator

#### Token Service

ออก JWT (RS256)

#### Audit Service

บันทึกเหตุการณ์ทั้งหมด

---

### ML Verifier

ให้บริการ Machine Learning แยกออกจาก Hub

หน้าที่

- รับ Feature Vector
- คำนวณ anomaly score
- ส่งคะแนนกลับ

พร้อม SHAP explanation

---

### Database

PostgreSQL

เก็บข้อมูล

- users
- access_list
- login_sessions
- audit_logs
- passkey_credentials
- subsystems

---

### Redis

เก็บข้อมูลชั่วคราว

- session
- authorization code
- MFA cache
- Step-up cache
- blacklist JWT

---

### Identity Provider

รองรับ

- Google
- Passkey

---
