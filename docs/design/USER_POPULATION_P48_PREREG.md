## 4. เกณฑ์ที่ต้องรายงาน (ขั้นที่ 7)

ทุกค่าต้องแยกตาม history size **50 / 100 / 500 / 1000 / 5000**:

1. **mean user FPR** ระดับประชากร
2. **median** และ **p90** ของ per-user FPR
3. **hierarchical / cluster CI** ของ mean
4. **จำนวนผู้ใช้ที่เกินงบ** (พร้อมรายชื่อ + ค่าของแต่ละคน เป็น outlier report แยก)
5. **Recall@challenge แยก attack family**
6. การกระจายของ per-user FPR (อย่างน้อย min / q25 / median / q75 / p90 / max)

**`maximum user FPR ≤ 1%` ห้ามใช้เป็น gate หลัก** — เมื่อจำนวนผู้ใช้เพิ่มขึ้น
ค่าสูงสุดจะสูงขึ้นเองตามธรรมชาติ (order statistic) ทำให้เกณฑ์เข้มขึ้นโดยไม่ได้ตั้งใจ
เมื่อขยายประชากร → ใช้ **mean + CI** และ **p90** เป็นเกณฑ์ และรายงาน outlier แยก

## 5. ลำดับที่ต้องทำตาม (ห้ามข้าม)

1. commit เอกสารนี้ **ก่อน** เขียน generator
2. สร้าง generator + roster (ขั้นที่ 4)
3. ตรวจ shortcut / leakage ของ generator (ขั้นที่ 5) — ถ้าพบ ต้องแก้ก่อนวัดใด ๆ
4. รัน Config B + baseline บน **P48-validation** เท่านั้น (ขั้นที่ 6)
5. รายงานตามเกณฑ์ §4 ด้วย cluster-aware CI (ขั้นที่ 7)
6. เปิด **P48-holdout** ครั้งเดียว เฉพาะเมื่อ validation ผ่าน (ขั้นที่ 8)
7. **ถ้าไม่ผ่าน หยุดที่ Shadow — ห้ามปรับ threshold ต่อ** (ขั้นที่ 9)
