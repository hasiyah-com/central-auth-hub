## หลักฐานและการประกอบสัญญาณ

กลุ่มอิสระที่นับ: (1) อุปกรณ์หรือ browser family ใหม่ (2) passkey ใหม่ที่การเข้าสู่ระบบ
ปัจจุบันไม่ได้ผ่าน strong primary (3) สิทธิ์ล่าสุดที่ไม่มีหลักฐานอนุมัติตรงรายการ
สองกลุ่มขึ้นไปทำให้ challenge โดยไม่ต้องรอคะแนน 0.70
การพบประเทศใหม่ ความล้มเหลวหลังปัจจัยแรกอย่างน้อย 3 ครั้ง หรือเหตุการณ์กู้บัญชี/รีเซ็ต
ภายใน 24 ชั่วโมง ร่วมกับอุปกรณ์/passkey/สิทธิ์ที่เปลี่ยน ก็ทำให้ challenge
บริบท strong primary และการอนุมัติไม่ลบคะแนน และไม่ยกเว้นสัญญาณประกอบเหล่านี้

Strong primary อ่านจากวิธีที่ backend ตรวจสำเร็จในครั้งนี้ (`passkey`, `discoverable`)
WebAuthn ต้องผ่าน user verification; ไม่รับ boolean จาก frontend ไม่อนุมานจากจำนวน
passkey และไม่อ่านประวัติ MFA เก่าของบัญชีมาใช้แทนการตรวจครั้งนี้
ไม่ได้เพิ่มการจำ MFA ข้าม session ด้วย IP/User-Agent เพราะทั้งสองไม่ใช่หลักฐานความเป็นเจ้าของ

การอนุมัติสิทธิ์ต้องตรงกับเวลาเปลี่ยนล่าสุดที่ feature extraction ใช้จริงในทุกระบบย่อย:
ต้องเป็นรายการ allow ที่ยังไม่ถูกถอน และมี audit `admin_grant_user_access` ตรง user,
ผู้ให้สิทธิ์, subsystem และเวลาหลัง grant ภายใน 5 วินาที ก่อนเวลาประเมิน
หากมีหลายรายการเปลี่ยนพร้อมกัน ทุกตัวต้องมีหลักฐาน ไม่ใช้การอนุมัติรายการอื่นมาแทน
แหล่งเก่า/การให้สิทธิ์จากช่องทางอื่นถือว่ายังไม่ทราบ ไม่ถือว่าได้รับอนุมัติอัตโนมัติ
หากอ่านหลักฐานไม่ได้ ใช้สถานะ unknown ไม่สร้างหลักฐานอนุมัติขึ้นมา

## คะแนนรวมและ MFA gate

คะแนนรวม L1+L2 ยังยกเป็น challenge ได้ที่ 0.70 แม้ไม่มี floor รวมถึง floor ของกฎรุนแรง
อื่นและชั้นพฤติกรรมยังคงเดิม Hard block, IP blacklist, impossible travel, burst,
concurrent และ incident ไม่ถูกลดความเข้มงวด

การตัดสินความเสี่ยงกับการขอ factor เพิ่มเป็นคนละขั้น: MFA policy เดิมถือว่า passkey
ที่ตรวจสำเร็จ satisfy strong authentication แล้ว จึงไม่ขอ factor เดิมซ้ำ ส่วน Google/LINE
ใช้ risk-based MFA และ Always-2FA gate เดิม การเปลี่ยนนี้ไม่เพิ่มการ bypass gate ดังกล่าว

บันทึก `risk_breakdown.rule_context` พร้อม policy version, strong primary, approval,
recovery/reset และสถานะหลักฐาน เพื่ออธิบายผลย้อนหลัง เหตุผล `contextual_stepup`
แสดงเมื่อ floor ใหม่ทำงาน; `contextual_change` หมายถึงไม่บังคับจากสัญญาณเปลี่ยนแปลงเดี่ยว
แต่เกณฑ์คะแนนหรือ floor อื่นยังอาจทำให้ challenge ได้

## การทดลองเดิม

`legacy_replay` คงผล frozen เดิมทั้งหมด รวม unconditional floors เพื่อทำซ้ำงานวิจัยเก่า
ผลการทดลอง/ตารางบทที่ 4 เดิมไม่ใช่ผลของ contextual-challenge-v1 ต้องทดลองชุดข้อมูลเดิม
แยกใหม่ก่อนรายงาน FPR/Recall ของนโยบายนี้ ยังไม่ได้วัดผลกับข้อมูล production
