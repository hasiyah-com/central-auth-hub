# วัตถุประสงค์ ขอบเขต และประโยชน์ที่ได้รับ

# ชื่อโครงการ

การพัฒนาระบบศูนย์กลางการยืนยันตัวตนและการควบคุมสิทธิ์การเข้าถึงด้วยการวิเคราะห์ความเสี่ยงแบบผสมผสาน (Hybrid Risk-Based Authentication) และการยืนยันตัวตนแบบ Passkey สำหรับระบบสารสนเทศมหาวิทยาลัย

---

# 1. วัตถุประสงค์ของโครงการ

## 1.1 วัตถุประสงค์หลัก

เพื่อพัฒนาระบบศูนย์กลางการยืนยันตัวตน (Central Authentication Hub) ที่สามารถให้บริการการเข้าสู่ระบบและการควบคุมสิทธิ์การเข้าถึงแก่ระบบย่อยต่าง ๆ ภายในมหาวิทยาลัย โดยใช้มาตรฐาน OAuth 2.0 ร่วมกับเทคนิคการวิเคราะห์ความเสี่ยงแบบผสมผสาน (Hybrid Risk-Based Authentication) และการยืนยันตัวตนแบบ Passkey เพื่อเพิ่มความปลอดภัย ลดความเสี่ยงจากการโจมตีบัญชีผู้ใช้ และปรับปรุงประสบการณ์การใช้งานของผู้ใช้

---

## 1.2 วัตถุประสงค์เชิงเทคนิค

### 1.2.1

เพื่อพัฒนาระบบ Single Sign-On (SSO) สำหรับระบบย่อยภายในมหาวิทยาลัย โดยใช้มาตรฐาน OAuth 2.0 Authorization Code Flow with PKCE

---

### 1.2.2

เพื่อพัฒนาระบบบริหารจัดการสิทธิ์การเข้าถึง (Role-Based Access Control: RBAC) ที่สามารถกำหนดสิทธิ์ตามบทบาทของผู้ใช้งานได้อย่างยืดหยุ่น

---

### 1.2.3

เพื่อพัฒนาระบบ Hybrid Risk-Based Authentication (Hybrid RBA) ที่สามารถประเมินความเสี่ยงของการเข้าสู่ระบบจากหลายปัจจัย ได้แก่

* Rule Engine
* Behavior Profiling
* Isolation Forest
* Risk Aggregation

และใช้ผลการประเมินดังกล่าวในการตัดสินใจด้านความปลอดภัย

---

### 1.2.4

เพื่อศึกษาการประยุกต์ใช้ Machine Learning ในการตรวจจับพฤติกรรมการเข้าสู่ระบบที่ผิดปกติ (Anomaly Detection) โดยใช้ Isolation Forest ร่วมกับ SHAP Explainability

---

### 1.2.5

เพื่อพัฒนาระบบการยืนยันตัวตนแบบ Passkey ตามมาตรฐาน WebAuthn/FIDO2 สำหรับลดการพึ่งพารหัสผ่านและเพิ่มความสามารถในการป้องกันการโจมตีแบบ Phishing

---

### 1.2.6

เพื่อพัฒนาระบบ Step-Up Authentication ที่สามารถเพิ่มระดับการยืนยันตัวตนเมื่อพบกิจกรรมที่มีความเสี่ยงสูง

---

### 1.2.7

เพื่อพัฒนาระบบบันทึกเหตุการณ์ด้านความปลอดภัย (Security Audit Logging) สำหรับสนับสนุนการตรวจสอบย้อนหลังและการวิเคราะห์เหตุการณ์ด้านความมั่นคงปลอดภัย

---

### 1.2.8

เพื่อประเมินประสิทธิภาพและความแม่นยำของระบบ Hybrid Risk-Based Authentication ในการลดความเสี่ยงจากการโจมตีบัญชีผู้ใช้และลดอัตรา False Positive

---

# 2. ขอบเขตของโครงการ

## 2.1 ขอบเขตด้านระบบงาน

ระบบที่พัฒนาจะทำหน้าที่เป็นศูนย์กลางการยืนยันตัวตนสำหรับระบบสารสนเทศภายในมหาวิทยาลัย โดยรองรับการเชื่อมต่อกับระบบย่อยหลายระบบผ่านมาตรฐาน OAuth 2.0

ตัวอย่างระบบย่อย ได้แก่

* ระบบหอพัก
* ระบบห้องสมุด
* ระบบทะเบียนนักศึกษา
* ระบบบุคลากร
* ระบบจัดการผู้ใช้งาน

---

## 2.2 ขอบเขตด้านการยืนยันตัวตน

ระบบรองรับ

### Authentication Methods

* Google OAuth Login
* Passkey Authentication (WebAuthn/FIDO2)
* Step-Up Authentication

---

### ไม่อยู่ในขอบเขต

* SMS OTP
* Hardware Token แบบ Legacy
* Social Login อื่นนอกเหนือจาก Google

---

## 2.3 ขอบเขตด้านการควบคุมสิทธิ์

ระบบรองรับ

* Role-Based Access Control (RBAC)
* Permission Management
* Subsystem Access Control

---

## 2.4 ขอบเขตด้าน Machine Learning

ระบบใช้ Machine Learning สำหรับการตรวจจับพฤติกรรมผิดปกติเท่านั้น

โดยใช้

* Isolation Forest
* SHAP Explainability

Machine Learning ไม่มีสิทธิ์อนุญาตหรือปฏิเสธผู้ใช้โดยตรง แต่ใช้เป็นส่วนหนึ่งของการประเมินความเสี่ยง

---

## 2.5 ขอบเขตด้าน Hybrid Risk-Based Authentication

ระบบประเมินความเสี่ยงจาก

### Layer 1

Rule Engine

ตัวอย่าง

* Blacklisted IP
* Failed Login Threshold
* Impossible Travel

---

### Layer 2

Behavior Profiling

ตัวอย่าง

* Login Time Pattern
* Device Pattern
* Location Pattern
* Subsystem Usage Pattern

---

### Layer 3

Isolation Forest

ใช้ตรวจจับ Anomaly จากข้อมูลพฤติกรรมผู้ใช้

---

### Layer 4

Risk Aggregator

รวมคะแนนความเสี่ยงจากทุก Layer เพื่อกำหนดผลลัพธ์

* Pass
* Step-Up Authentication
* Block

---

## 2.6 ขอบเขตด้านความปลอดภัย

ระบบรองรับ

* OAuth 2.0 with PKCE
* JWT RS256
* Passkey Authentication
* Audit Logging
* Rate Limiting
* Session Protection
* Threat Modeling (STRIDE)
* Security Verification
* Penetration Testing

---

## 2.7 ขอบเขตการประเมินผล

ประเมินผลโดยใช้

### Functional Testing

* Unit Testing
* Integration Testing
* End-to-End Testing

---

### Security Testing

* OAuth Security Testing
* Passkey Security Testing
* Access Control Testing
* API Security Testing

---

### Machine Learning Evaluation

* Precision
* Recall
* F1-Score
* False Positive Rate
* False Negative Rate
* SHAP Analysis

---

# 3. ประโยชน์ที่คาดว่าจะได้รับ

## 3.1 ประโยชน์ต่อองค์กร

### ลดความซ้ำซ้อนของระบบยืนยันตัวตน

ระบบย่อยสามารถใช้บริการยืนยันตัวตนจากศูนย์กลางร่วมกันได้ ลดภาระในการพัฒนาระบบ Login แยกแต่ละระบบ

---

### เพิ่มความปลอดภัยของระบบสารสนเทศ

สามารถตรวจจับพฤติกรรมผิดปกติและตอบสนองต่อความเสี่ยงได้แบบอัตโนมัติ

---

### รองรับการขยายระบบในอนาคต

สามารถเพิ่มระบบย่อยใหม่ได้โดยไม่ต้องพัฒนาระบบยืนยันตัวตนใหม่

---

## 3.2 ประโยชน์ต่อผู้ใช้งาน

### ลดจำนวนบัญชีผู้ใช้

ผู้ใช้สามารถเข้าสู่ระบบหลายระบบด้วยบัญชีเดียว

---

### เพิ่มความสะดวกในการเข้าสู่ระบบ

รองรับการใช้งาน Passkey ซึ่งไม่จำเป็นต้องจดจำรหัสผ่าน

---

### ลดผลกระทบจากการโจมตีแบบ Phishing

Passkey มีความสามารถในการป้องกันการโจมตีแบบ Phishing ได้ดีกว่าการใช้รหัสผ่านแบบดั้งเดิม

---

## 3.3 ประโยชน์ด้านความมั่นคงปลอดภัย

### ตรวจจับความเสี่ยงแบบเชิงรุก

Hybrid RBA สามารถวิเคราะห์พฤติกรรมและตรวจจับความผิดปกติได้ก่อนเกิดความเสียหาย

---

### ลดความเสี่ยงจาก Account Takeover

ใช้การประเมินความเสี่ยงร่วมกับ Step-Up Authentication และ Passkey

---

### เพิ่มความสามารถในการตรวจสอบย้อนหลัง

Audit Logging ช่วยสนับสนุนการตรวจสอบเหตุการณ์ด้านความปลอดภัย

---

## 3.4 ประโยชน์ด้านงานวิจัย

### ศึกษาการประยุกต์ใช้ Machine Learning กับระบบ Identity and Access Management

---

### ศึกษาการประยุกต์ใช้ Explainable AI (SHAP)

เพื่อเพิ่มความโปร่งใสในการตัดสินใจของระบบ

---

### เป็นแนวทางในการพัฒนาระบบ Adaptive Authentication

สำหรับสถาบันการศึกษาและองค์กรอื่นในอนาคต

---

# 4. ผลลัพธ์ที่คาดหวัง

เมื่อสิ้นสุดโครงการจะได้ระบบ Central Authentication Hub ที่สามารถ

* ให้บริการ Single Sign-On
* บริหารจัดการสิทธิ์ผู้ใช้งาน
* ตรวจจับพฤติกรรมผิดปกติ
* ประเมินความเสี่ยงแบบอัตโนมัติ
* รองรับ Passkey Authentication
* รองรับ Step-Up Authentication
* บันทึกและตรวจสอบเหตุการณ์ด้านความปลอดภัย
* เพิ่มความปลอดภัยของระบบสารสนเทศมหาวิทยาลัย
* ลดความเสี่ยงจากการโจมตีบัญชีผู้ใช้งาน
* รองรับการขยายตัวของระบบในอนาคต
