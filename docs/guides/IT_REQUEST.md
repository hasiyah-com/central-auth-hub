# เอกสารขอทรัพยากร IT — โปรเจค Central Auth Hub (ปริญญานิพนธ์)

สำหรับยื่นฝ่าย IT/Network ของมหาวิทยาลัย เพื่อขอทรัพยากรติดตั้งระบบสาธิต

**ผู้ขอ:** (ชื่อ-นามสกุล / รหัสนักศึกษา)
**โปรเจค:** ระบบจัดการสิทธิ์ผู้ใช้แบบศูนย์กลาง (Central Auth Hub) — senior project
**ลักษณะระบบ:** Auth server (OAuth 2.0 + Passkey) + 2 ระบบย่อย (หอพัก/ห้องสมุด) ทำงานบน Docker

---

## สรุปสิ่งที่ขอ (เลือกได้ตามที่มหาลัยรองรับ)

ระบบต้องการ **VM 1 เครื่อง** สำหรับ Hub (auth server) ส่วนระบบย่อยรันบนเครื่องของผู้พัฒนาเอง
ขอความอนุเคราะห์ข้อใดข้อหนึ่ง ตามที่นโยบายมหาลัยเอื้ออำนวย:

### แบบ A — ใช้งานภายในเครือข่ายมหาลัย (สาธิตในห้องสอบ) — ขั้นต่ำ
- ขอแค่ให้ VM **ต่อเครือข่ายมหาลัยแบบ bridged** เพื่อรับ IP ภายใน (campus IP)
- **ไม่ต้องการ** public IP / domain / เปิด port ออกอินเทอร์เน็ต
- ใช้ใบรับรอง HTTPS แบบ self-signed/internal CA เอง
- > เพียงพอสำหรับการสาธิตถ้าผู้ชม/กรรมการอยู่ในเครือข่ายมหาลัยเดียวกัน

### แบบ B — เข้าถึงจากภายนอกได้ (ถ้านโยบายเอื้อ)
1. **Subdomain 2 ตัว** ชี้มาที่ IP ของ VM:
   - `admin.<ชื่อที่จัดสรร>` (หน้าเว็บผู้ดูแล)
   - `auth.<ชื่อที่จัดสรร>` (auth server)
   - หรือขอ **wildcard** `*.<ชื่อ>` ก็ครอบคลุม
2. **Public IP** ให้ VM + เปิด **inbound TCP port 80 และ 443**
   - port 80 จำเป็นสำหรับออกใบรับรอง Let's Encrypt (HTTP-01 challenge)
3. ถ้าออก Let's Encrypt ไม่ได้ → ขอ **ใบรับรอง SSL ของมหาลัย / internal CA** สำหรับ subdomain ข้างต้น

## คำถามที่อยากให้ IT ช่วยตอบ

| # | คำถาม | เหตุผลที่ต้องรู้ |
|---|---|---|
| 1 | VM ที่ bridged เข้าเครือข่ายมหาลัย จะได้ IP แบบใด (campus-internal / public)? | กำหนดว่าทำแบบ A หรือ B |
| 2 | เปิด inbound port 80, 443 มาที่ VM ได้ไหม? | จำเป็นต่อ HTTPS + ให้ระบบย่อยต่อเข้า Hub |
| 3 | จัดสรร subdomain (หรือ wildcard) ให้ได้ไหม? | Passkey/WebAuthn ต้องใช้ชื่อโดเมน (ใช้ IP ไม่ได้) |
| 4 | รองรับ Let's Encrypt ไหม หรือมี internal CA ให้ใช้? | สำหรับใบรับรอง HTTPS |
| 5 | มี firewall/proxy ของมหาลัยกั้น traffic ระหว่างเครื่องในเครือข่ายไหม? | ระบบย่อย (เครื่องผู้พัฒนา) ต้องต่อเข้า Hub (VM) ได้ |

## หมายเหตุด้านความปลอดภัย

- เปิด public เฉพาะ port 80/443 (ผ่าน Nginx reverse proxy + TLS) เท่านั้น
- ฐานข้อมูล (PostgreSQL), Redis, ML service **ไม่เปิดออกสู่ภายนอก** (อยู่ใน Docker network ภายใน)
- เป็นระบบสาธิตเชิงวิชาการ ไม่มีข้อมูลผู้ใช้จริงของมหาวิทยาลัย (ใช้ข้อมูลทดสอบที่สร้างขึ้น)
