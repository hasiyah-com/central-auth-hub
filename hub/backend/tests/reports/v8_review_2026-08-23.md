## 3. ❌ สิ่งที่ยังพิสูจน์ไม่ได้ (จุดชี้ขาด)

### 3.1 ยังทดสอบแค่บน generator ตัวเอง
ROC-AUC **0.998** · sequence detection 96.85% — **บน synthetic attack ของ V8 เอง**
**นี่คือรูปแบบเดียวกับ V7** ที่ ROC-AUC 0.998 บนข้อมูลตัวเอง แต่**ตกเหลือ 0.617 บนชุด V2 ของผม**
(12 โปรไฟล์ anchor คนจริง) → **การทดสอบที่ชี้ขาดคือรันบนข้อมูลนอก generator ยังไม่ได้ทำ**

### 3.2 shortcut ที่ยังอาจเหลือ
neural รับ **duration + browser drift** ซึ่งเป็น 2 ใน shortcut ที่ผมพบ
(`duration_log_range` หลุด support 62%, `browser_version_slope` 40%) — attack V8 ก็ยังใช้
"ค่อยๆ เพิ่ม duration/scope" และ "browser drift ทีละน้อย"
→ artifact audit จับ **one-sided** shortcut (เช่น success_10m ที่ normal=0 เสมอ) แต่ **ramp
ของ duration เป็น two-sided** (normal แบน / attack ไต่ขึ้น) — **ต้องยืนยันว่า audit จับเคสนี้ด้วย**

### 3.3 MLP เพิ่มค่าเหนือ Rule/Behavior จริงไหม
learning curve ของผม: Rule/Behavior ให้ recall **87% ตั้งแต่ 10 event**
V8 MLP activate เมื่อ ≥1,000 event และได้ event recall **68.9%**
→ **ต้องมี ablation: Rule/Behavior เดี่ยว vs +MLP** สำหรับกลุ่ม ≥1,000 event
ถ้า MLP ไม่ได้เพิ่ม recall/policy อย่างมีนัย = complexity ที่ไม่คุ้ม

## 5. V8 กระทบแผน Phase 1 ไหม

**ไม่กระทบ — เสริมกันด้วยซ้ำ**
- Phase 1 (rule-based, port เข้า production แล้ว) = **base layer ที่ V8 พึ่งพาตอน cold-start**
  (V8 เขียนเอง: profile < 1,000 event → ใช้ Rule/Behavior/MFA เดิม)
- V8 = **shadow layer เสริม** สำหรับผู้ใช้ที่มี history เยอะ — ตรงกับแผนระยะยาวที่ผมเสนอ
  (sequence layer เป็นชั้นเสริมของ V3/Rule ไม่ใช่ตัวแทน)
- ต่างจาก V6/V7 ตรงที่ V8 **ไม่พยายามแทนที่ rule** และ **abstain แทนที่จะเดา** — ปรัชญาถูกแล้ว

> V8 คือทิศทางที่ถูก — ยังขาดแค่ "หลักฐานว่า generalize" ซึ่งได้จากการรันบนข้อมูลนอก (ข้อ 2)
