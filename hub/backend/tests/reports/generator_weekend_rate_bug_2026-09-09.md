## 1. อาการ

`docs/design/USER_POPULATION_P48_PREREG.md` ประกาศ `weekend_rate` ว่าเป็น
**สัดส่วนของ login ที่เกิดในวันเสาร์-อาทิตย์**

```
weekend_rate = 0 (25%) / uniform(0.02, 0.15) (50%) / uniform(0.15, 0.40) (25%)
```

แต่ค่าที่ **สังเกตได้จริง** จากข้อมูลที่ generate ออกมามีเพดานเพียง 0.1266
— ต่ำกว่าค่าสูงสุดที่ประกาศไว้ (0.40) ราว 3 เท่า

พบระหว่างเทียบ distribution ของ traffic จริงกับ P48
(`real_vs_p48_distribution_2026-09-09.md`) โดยผู้ใช้จริงกลุ่ม local มีสัดส่วน
วันหยุดมัธยฐาน **0.381** ซึ่งอยู่นอกช่วงที่ P48 สร้างได้ทั้งหมด (6/6 คน)

### 2.4 สาเหตุ — การตีความพารามิเตอร์ผิด ไม่ใช่ sampling หรือ episode calendar

สัดส่วนที่ได้เป็นไปตามสูตร

```
observed = (n_weekend × rate) / (n_weekday + n_weekend × rate)
```

ตรวจกับค่าที่วัดได้: `rate = 0.40` → `(8 × 0.4) / (22 + 8 × 0.4) = 0.127` ตรงกับ 0.1278

**นัยสองข้อ**

1. ค่าที่ได้ **ต่ำกว่าค่าที่ประกาศเสมอ** ประมาณ 0.27–0.37 เท่า
2. มี **เพดานที่ 0.2667** (สัดส่วนวันหยุดในปฏิทิน) แม้ตั้ง `rate = 1.0`
   → พฤติกรรมผู้ใช้จริงที่ 0.381 **สร้างไม่ได้เลยที่ค่าพารามิเตอร์ใด ๆ**

ไม่ใช่ปัญหาการสุ่ม (วัดที่ `n = 20,000` ความคลาดเคลื่อนเชิงสุ่มเล็กกว่ามาก)
ไม่ใช่ปัญหา episode calendar (วัดที่ระดับ `spread_over_days` โดยตรง)
ไม่ใช่ field ไม่ถูกต่อสาย (`build_profiles_v2.py:549` อ่านค่าไปใช้จริง)

## 3. ผลกระทบต่อผลการทดลองที่ freeze ไว้แล้ว

**ไม่ทำให้ผลของ P48 เป็นโมฆะ** — ตัวเลข FPR และ recall ที่รายงานไว้ยังเป็นผลที่
ถูกต้องของประชากรที่ generate ออกมาจริง

**แต่จำกัดสิ่งที่อ้างได้** — ห้ามใช้ P48 อ้างเรื่อง temporal realism หรืออ้างว่า
ครอบคลุมผู้ใช้ที่ทำงานวันหยุดเป็นหลัก เพราะประชากรนั้นไม่เคยถูกสร้างขึ้นเลย

ต้องเพิ่มข้อจำกัดนี้ในรายงานที่อ้างถึง P48 ทุกฉบับ

## 4. วิธีแก้ที่ตกลงกันแล้ว (ยังไม่ลงมือ)

แปลงสัดส่วนเป้าหมายเป็นน้ำหนัก โดยคำนึงถึงจำนวนวันแต่ละชนิดในช่วงนั้น

```
w_weekend = (p × n_weekday) / ((1 − p) × n_weekend)
w_weekday = 1.0
```

ตัวอย่าง 30 วัน (วันธรรมดา 22 · วันหยุด 8) ต้องการ 30%

```
w_weekend = (0.30 × 22) / (0.70 × 8) = 1.1786
```

### กรณีขอบเขตที่ต้องรองรับ

| กรณี | พฤติกรรมที่ต้องการ |
|---|---|
| `p = 0` | ไม่สร้าง login วันหยุดเลย |
| `0 < p < 1` | ใช้สูตรแปลงน้ำหนัก |
| `p = 1` | สร้างเฉพาะวันหยุด |
| ไม่มีวันหยุดหรือไม่มีวันธรรมดาในช่วง | fail พร้อมข้อความชัดเจน |

### เกณฑ์ยอมรับหลังแก้

```
| observed − target | <= max(0.02, sampling_CI)
```

| เป้าหมาย | ช่วงที่ยอมรับ |
|---|---|
| 0.05 | 0.03 – 0.07 |
| 0.15 | 0.13 – 0.17 |
| 0.30 | 0.28 – 0.32 |
| 0.40 | 0.38 – 0.42 |
