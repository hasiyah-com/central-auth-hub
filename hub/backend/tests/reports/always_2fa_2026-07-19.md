# Test Report — Always-2FA (user choice) + Security Onboarding

**วันที่:** 2026-07-19 · **แผน:** `plan/always-2fa-user-choice.md`

## เป้าหมาย
หลัง login Google → ชวนตั้ง factor (passkey/TOTP/ทั้งสอง) + เปิด "ขอ 2FA ทุก login" ได้เอง
**โดยไม่ซ้ำซ้อนกับ Risk-Based MFA** (ยุบเป็น gate เดียว — ยืนยันครั้งเดียว). admin ถูกบังคับ.

  local ยังไม่ได้ `npm i` (dev build ไม่ขึ้น)

### Manual E2E (บน stack ที่รันจริง)
1. user ไม่มี factor login → การ์ด SecurityOnboarding ขึ้น → เลือกทาง → ไป /account scroll ถูกจุด
2. เปิด Always-2FA ที่ /account → logout → login Google ใหม่ → เด้ง risk-stepup (ไม่ขึ้น "ตรวจพบ
   ความเสี่ยง" เพราะไม่ใช่ risk) → ยืนยัน passkey/TOTP → เข้าได้
3. user มี TOTP ไม่มี passkey + always-on → login → risk-stepup โชว์ TOTP (ไม่ force-enroll passkey)
4. admin → /account toggle ล็อก ON · login → ต้อง 2FA เสมอ
5. เสี่ยงกลาง + always-on → **ยืนยันครั้งเดียว** (ไม่ซ้อน)

## รอบ 2 (2026-07-21) — ครอบคลุมทุก role + ปุ่ม "เพิ่มการยืนยันตัวตน" + snooze

### ปัญหาที่เจอตอนเทสจริง
การ์ด onboarding ขึ้นแค่ admin — เพราะ **นักศึกษาถูกบล็อก Hub-direct login**
([auth.py `hub_login_blocked_student`](../../app/routers/auth.py)) จึงเข้า Hub console ไม่ได้เลย
ส่วน staff/teacher ไม่ขึ้น = **ถูกต้อง** (มี passkey อยู่แล้ว — ยืนยันจาก DB)

### แก้
- **OAuth interstitial** (`oauth.py`) — gate `count_active==0` → `mfa_policy.should_prompt_setup`
  (รู้จัก TOTP + เคารพ snooze/dismiss) · เพิ่มทางเลือก **Authenticator (TOTP)** พร้อม QR
  (`/oauth/totp/enroll/start|verify` ใช้ `hub_state` ไม่ต้องมี JWT) · ปุ่ม "ไม่ต้องถามอีก"
  · "ข้ามไปก่อน" → `?action=skip` (snooze 7 วัน)
- **ปุ่ม "เพิ่มการยืนยันตัวตน"** — `GET /auth/credentials/setup` (auth.py) → Google login →
  callback ที่ `setup_intent` **ไม่ออก JWT + ข้าม student block** → หน้าตั้ง credential
  (reuse interstitial + enroll context). **นักศึกษาใช้ได้โดยไม่ต้องแก้ RBAC** และ
  **ไม่ต้องเพิ่ม redirect URI ใน Google Console** (reuse `/auth/google/callback` + session flag)
- **`/oauth/continue`** — รองรับ standalone (ไม่มี `authreq`) → หน้าสรุปแทน redirect subsystem
- **snooze** — `users.security_onboarding_snoozed_until` (migration `c3d4e5f6a7b8`) +
  `mfa_policy.should_prompt_setup/snooze_onboarding` + endpoint `snooze-onboarding`
- **`totp_service.qr_svg()`** — render QR เป็น SVG ฝั่ง server (dep ใหม่ `qrcode==8.0`, fail-safe → "")
- Frontend — ปุ่มที่หน้า login · การ์ดใช้ `should_prompt_setup` · "ไว้ทีหลัง" → snooze API (ผูกบัญชี)

## รอบ 3 (2026-07-21) — รื้อ UI หน้า enroll + Always-2FA สำหรับนักศึกษา

### ปัญหาที่เจอตอนเทสจริง (นักศึกษา login เข้าระบบหอพัก)
1. หน้า interstitial **ไม่มีให้เลือกวิธี** — ยัด device name + ปุ่ม passkey + ปุ่ม TOTP + QR
   + ช่องรหัส กองรวมหน้าเดียว
2. ปุ่ม "ข้ามไปก่อน / ไม่ต้องถามอีก" อยู่**ใต้ QR** ต้องเลื่อนลงไปมาก หาไม่เจอ
3. **QR ขาวโล่ง** — container ยังไม่ได้ rebuild หลังเพิ่ม dep `qrcode` → `qr_svg()` fail-safe คืน ""
4. ปุ่ม "เพิ่มการยืนยันตัวตน" อยู่**แค่หน้า login ของ Hub** ซึ่งนักศึกษาเข้าไม่ได้
5. **Always-2FA ตั้งได้แค่ที่ `/account`** ซึ่งนักศึกษาเข้าไม่ได้เช่นกัน

### แก้ (`oauth.py`)
- **รื้อ `_passkey_enroll_html` ใหม่ทั้งหน้า** เป็น 2 ขั้น:
  ขั้น 1 การ์ดเลือกวิธี (🔑 Passkey [แนะนำ] / 📱 Authenticator) → ขั้น 2 แผงตั้งค่าเฉพาะวิธีที่เลือก
  (มีปุ่ม "‹ เลือกวิธีอื่น" ย้อนกลับ)
- ปุ่ม **ข้ามไปก่อน / ไม่ต้องถามอีก** ย้ายมาเป็นปุ่มคู่ในขั้นเลือกวิธี — เห็นทันทีไม่ต้องเลื่อน
- **checkbox "ขอยืนยันตัวตนทุกครั้งที่ล็อกอิน"** ในขั้นเลือกวิธี → ส่ง `mfa_always` ไปกับ
  `passkey/enroll/finish` และ `totp/enroll/verify` (ทางเดียวที่นักศึกษาเปิด Always-2FA ได้)
  · `_apply_mfa_always()` **เปิดได้อย่างเดียว ปิดไม่ได้** (กัน attacker ยึด enroll context
  ไปปลดการป้องกัน — การปิดต้องทำที่ `/account` ผ่าน step-up)
- **login chooser page** (หน้าที่นักศึกษาเห็นทุกครั้งที่เข้าระบบย่อย) เพิ่มลิงก์
  "🛡️ ตั้งค่า Passkey / Authenticator ของบัญชี" → `/auth/credentials/setup`
  (คนที่เคยกด "ข้าม/ไม่ถามอีก" มีทางกลับมาตั้งเอง)

### Verify (browser จริง — ผ่าน static render)
- โครง 3 ขั้นถูกต้อง: `stepChoose=block`, `stepPasskey=none`, `stepTotp=none`, modal ซ่อน
- **QR render ถูกต้อง**: SVG 164×164, `path` fill `rgb(0,0,0)` → ยืนยันว่าโค้ดไม่ได้พัง
  ที่เห็นขาวคือ container ยังไม่ rebuild

- checkbox คลิกได้ → `wantAlways()` คืน `true`

## รอบ 4 (2026-07-21) — แก้ "ถูกบังคับเพิ่ม passkey ซ้ำ" + popup ถาม Always-2FA

### ปัญหาที่เจอตอนเทสจริง
user ที่**มี passkey อยู่แล้ว** เข้าหน้า "เพิ่มการยืนยันตัวตน" เพื่อเปิด Always-2FA
→ ถูกบังคับให้ enroll passkey ใหม่ เพราะ checkbox จะถูกบันทึกก็ต่อเมื่อ enroll สำเร็จเท่านั้น

### แก้
- **ขั้น "จัดการ" (`stepManage`)** — แสดงเป็นขั้นแรกเมื่อ `has_passkey or has_totp`:
  สถานะแต่ละ factor · ปุ่ม **เปิด Always-2FA ทันที** (ไม่ต้อง enroll ซ้ำ) ·
  "เพิ่มอีกวิธี" (ไป `stepChoose`) · "เสร็จแล้ว"
  ถ้าเปิด Always อยู่แล้ว → แสดงแถบ ✓ แทนปุ่ม
- **Endpoint ใหม่** `POST /oauth/security/always-2fa` `{hub_state}` —
  เปิด Always-2FA จาก enroll context โดยไม่ต้อง enroll · **เปิดได้อย่างเดียว** ·
  **400 `no_factor`** ถ้ายังไม่มี factor (กันเปิดแล้วล็อกตัวเองออก)
- **Popup หลังตั้งค่าเสร็จ** (`alwaysModal`) — ถ้า user ไม่ได้ติ๊ก checkbox ไว้ก่อน
  และยังไม่เปิด Always → เด้งถาม "เปิด — ขอทุกครั้ง / ไม่ต้อง — ขอเฉพาะตอนเสี่ยง"
  · ติ๊กไว้ก่อนแล้ว → ไปต่อเลยไม่ถามซ้ำ (flow ปกติตามที่ user ต้องการ)
  · เส้นทาง backup codes → เก็บ codes เสร็จค่อยถาม
  · กด "เปิด" แล้ว API ล้ม → **ยังเข้าระบบได้** (fail-safe ไม่ขวาง)
- `auth.py` (`/auth/credentials/setup`) ส่ง `has_passkey/has_totp/mfa_always` จริงเข้าหน้า

| กรณี | ขั้นแรก | ผล |
|---|---|---|
| ยังไม่มี factor | `stepChoose` | เลือกวิธีตามปกติ |
| มี passkey แล้ว | `stepManage` | สถานะ "🔑 ✓ ตั้งค่าแล้ว / 📱 ยังไม่ได้ตั้ง" + ปุ่มเปิด Always |
| มีครบ + always on | `stepManage` | ไม่มีปุ่ม → แถบ "✓ เปิดอยู่แล้ว" |
