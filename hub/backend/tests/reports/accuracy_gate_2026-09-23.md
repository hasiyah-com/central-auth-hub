## 3. การแบ่งข้อมูลและการเทียบที่ FPR เท่ากัน

| ชุด | ข้อมูล | หน้าที่ |
|---|---|---|
| Train / Calibration (ECDF) | split ภายในผู้ใช้ของแต่ละ cell (`DS.build`) | fit โมเดล + ECDF (เดิม) |
| **Calibration ของรอบนี้** | P48-T2 validation profiles × seed **[401–405]** (เห็นแล้ว) | ตั้ง threshold ให้ FPR เท่ากัน + เลือกพารามิเตอร์ G |
| **Validation** | P48-T2 validation profiles × seed **[501–505]** (ใหม่) | ตัดสิน gate ครั้งเดียว |
| Final holdout | holdout 16 โปรไฟล์ของ P48-T2 | **ไม่เปิดในรอบนี้** |

- ทุก candidate ตั้ง threshold บน calibration ให้ **challenge FPR ≤ 0.5% และ block FPR ≤ 0.1% ทุกขนาด**
  (`pick_threshold` บน grid 0.400–0.995 ทีละ 0.005 · ต่ำกว่างบเพื่อเผื่อ tail shift ข้ามประชากรที่เคยวัดได้
  0.73% → 1.18%) · ถ้าไปไม่ถึง (FPR จาก policy floor) ต้องรายงาน `reachable=false`
- แล้วใช้ threshold เดียวกันนั้นบน validation — ไม่ปรับอีก

## 4. Candidate

| key | ความหมาย |
|---|---|

### 4.1 G — grid และกฎการเลือก (บน calibration เท่านั้น)

`ambiguous_low ∈ {0.30, 0.40, 0.50}` × `w_point ∈ {0.5, 1.0}` × `w_sequence ∈ {0.5, 1.0}` ×
`low_zone_agree ∈ {0.90, 0.95}` = 24 ชุด · แต่ละชุดตั้ง threshold ของตัวเองตามข้อ 3 แล้วเลือกด้วย `select_g`:

1. recall@challenge เฉลี่ยของ 6 ตระกูลในข้อ 2.1 สูงสุด
2. severe recall สูงสุด
3. challenge FPR ต่ำสุด
4. น้ำหนักรวมน้อยสุด

ชุดที่ไปไม่ถึง FPR เป้าถูกตัดทิ้งก่อน · เลือกแล้ว freeze ก่อนแตะ validation

### 4.2 การออกแบบของ G ที่ตรึงไว้ตอน implement (ก่อนวัดใด ๆ · commit ระยะที่ 5)

- ขอบบนของช่วงกำกวม `AMBIGUOUS_HIGH` = **0.70 คงที่** (ค่า challenge เริ่มต้นของ production) ไม่ผูกกับ threshold
  ที่กวาด → คะแนนของ G ไม่ขึ้นกับ threshold จึงกวาดหา FPR เท่ากันผ่าน `resolve_action` ตัวเดียวกับ B/E ได้
- "ยกได้สูงสุด warn" ในช่วงเสี่ยงต่ำ ส่งผ่าน `ResolverInput.action_cap` (ใหม่ · ค่าเริ่มต้น None ไม่เปลี่ยน B/E) ·
  policy floor ชนะเพดานเสมอ · L3 ห้าม block คนเดียวทุกช่วง (`SOLO_BLOCK_FORBIDDEN` เดิม)
- ช่วง high ใช้ L3 เป็นหลักฐานสนับสนุนด้วย gamma เดียวกับ fusion เดิม
- production: `L3_CONDITIONAL_PARAMS` (JSON) ว่าง = ไม่คำนวณ · ตั้งแล้วบันทึก `conditional_shadow` ใน
  `risk_breakdown` เป็นผลจำลองชุดที่สาม เฉพาะโหมด `shadow_hybrid`/`hybrid_stepup` · key ผิด/ค่าผิดช่วง = ไม่ start

### 6.8 สรุปและสิ่งที่ตามมา

1. **Accuracy Gate ไม่ผ่าน** — G ไม่ถึงเป้าของตระกูลที่อ่อนและ campaign recall · ไม่เปิด holdout ·
   ไม่เปิด Shadow Pilot · ไม่เปิด L3 enforcement
2. **ที่ FPR เท่ากัน L3 ในรูปแบบปัจจุบันทำให้แย่ลง** — ทั้ง E และ G จับได้น้อยกว่า baseline L1+L2 ·
   กลไกคือหลักฐาน L3 ดันคะแนนของเหตุการณ์ปกติขึ้นด้วย ทำให้ threshold ที่คุม FPR ต้องสูงขึ้น
   และการจับที่มาจาก "คะแนน" (ไม่ใช่ policy floor) หายไป
3. **conditional fusion แก้ได้บางส่วน** (+7.0 จุดเทียบ E) เพราะจำกัดอิทธิพลของ L3 ในช่วงเสี่ยงต่ำ
   แต่ไม่พอจะชนะ baseline
4. ผลนี้สอดคล้องกับข้อจำกัดที่บันทึกไว้ตั้งแต่ freeze 29 ส.ค.: L3 ยังไม่มีหลักฐานว่าเพิ่มคุณค่าบนข้อมูลจริง
5. ทางเลือกถัดไป (ต้องเลือกและ pre-register ก่อนวัดใหม่ · ห้ามวัดชุดเดิมซ้ำ):
   (ก) ปรับ calibration ของ L3 ให้หลักฐานบนเหตุการณ์ปกติต่ำลง แทนการปรับวิธี fusion
   (ข) นิยามช่วงกำกวมจากควอนไทล์ของคะแนน L1/L2 จริงแทนค่าคงที่ 0.70
   (ค) ใช้ L3 เป็นช่องเฝ้าระวังอย่างเดียว (ไม่เข้าแกนการตัดสิน) ซึ่งเป็นสถานะปัจจุบันของ production
   (ง) ยอมรับว่าที่ FPR เท่ากัน L3 ยังไม่เพิ่มคุณค่า และรายงานตามนั้นในเล่ม

### 10.3 ความซ้ำซ้อนกับ baseline (ข้อมูลประกอบ)

### 10.4 สรุป

1. **tail transform แก้ปัญหาที่ตั้งใจแก้ได้จริง** — ลด threshold ที่ต้องใช้ และกู้ recall กลับมาได้
   ราวสองในสามของที่ C เสียไป (paired delta −0.123 → −0.048)
2. **แต่ยังแพ้ baseline อย่างมีนัย** → candidate H **ไม่ผ่าน** ตามเกณฑ์ที่ลงทะเบียนไว้
3. **สาเหตุที่แท้จริงชัดขึ้นจาก §10.3: ความซ้ำซ้อน ไม่ใช่แค่สเกล** — point เห็นสิ่งที่ L1/L2 เห็นอยู่แล้ว
   เกือบทั้งหมด (unique 11 เหตุการณ์) ดังนั้นไม่ว่าจะแปลงคะแนนอย่างไร มันก็แทบไม่เพิ่มการตรวจจับ
   แต่ยังกินงบ FPR อยู่ดี · นี่ตอบคำอธิบายข้อ 3 ใน §8.3 และลดน้ำหนักของข้อ 1 ลง
4. **ผล §6 (Accuracy Gate = failed) ไม่เปลี่ยน** · รอบนี้ประกาศว่า Gate ผ่านไม่ได้และไม่ได้ประกาศ
5. ทิศทางที่หลักฐานชี้ตอนนี้: ตัวเลือก **ค** (คง L3 เป็นช่องเฝ้าระวัง) มีน้ำหนักมากขึ้น เพราะปัญหาไม่ใช่
   การแปลงคะแนน แต่เป็นการที่ point ไม่เห็นอะไรใหม่เกินจาก L1/L2 บนประชากรนี้ ·
   ถ้าจะดัน L3 ต่อ ต้องหาสัญญาณที่ L1/L2 ไม่มี ไม่ใช่ปรับสเกลของสัญญาณเดิม
