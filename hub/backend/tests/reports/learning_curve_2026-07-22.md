# Learning Curve — ต้องใช้ข้อมูลเทรนกี่แถวถึง "พอ"

**วันที่:** 2026-07-22
**สคริปต์:** `ml-service/scripts/learning_curve.py`
**โมเดล:** Isolation Forest (`n_estimators=100`, `contamination=0.02`) — พารามิเตอร์เดียวกับ `train_model.py`

```bash
docker compose exec ml-service python -m scripts.learning_curve
```

---

## 1. คำถามที่ตอบ

> "ชุดข้อมูลสำหรับเทรน ต้องมีกี่แถวถึงจะแยกพฤติกรรมปกติ/ผิดปกติได้แม่นยำ?"

**วิธี:** เทรนด้วยจำนวนข้อมูลเพิ่มขึ้นทีละขั้น (1,000 → 14,000) แล้ววัด
Precision / Recall / F1 / ROC-AUC บน **test set ชุดเดียวกันตลอด**
→ ถ้าค่าเริ่มนิ่ง (plateau) แปลว่าข้อมูลเพียงพอแล้ว

---

## 2. การออกแบบการทดลอง

| หลักการ | เหตุผล |
|---|---|
| **Test set คงที่ทุกขนาด** (normal 4,000 + anomaly 400) | ถ้าเปลี่ยน test set ด้วยจะเทียบกันไม่ได้ |
| **Nested subsample** | ชุด 1,000 ⊂ 3,000 ⊂ 5,000 … → ลด noise ทำให้เส้นโค้งเรียบ |
| **เฉลี่ย 3 seed ต่อขนาด** | กันบังเอิญสุ่มได้ชุดที่ดี/แย่เป็นพิเศษ |
| **นับเฉพาะ normal** | Isolation Forest เทรน unsupervised ด้วย normal เท่านั้น (`fit(X_train_normal)`) |
| **Pool แยกต่างหาก** | ไม่แตะ `sessions.csv` / `iforest_v1.pkl` ของ production |

**Pool:** normal 20,000 + anomaly 1,000 (สร้างจาก `generate_data.py` seed 42)
**Train pool หลังหัก test:** normal 16,000

## 4. ข้อสรุป ⭐

### ✅ ค่านิ่งตั้งแต่ n ≈ 3,000
เกณฑ์: `|ΔF1| < 0.01` และ `|ΔAUC| < 0.01`

**ตั้งแต่ 3,000 เป็นต้นไป การเพิ่มข้อมูลไม่ช่วยให้ดีขึ้นอย่างมีนัยสำคัญ**

### รายละเอียดที่น่าสนใจ

| ประเด็น | ผล |
|---|---|
| **ROC-AUC นิ่งตั้งแต่ 1,000** | 0.9901–0.9912 (แกว่งเพียง **0.0011** ตลอดช่วง) — โมเดลแยกความผิดปกติได้ดีตั้งแต่ข้อมูลน้อย |
| **F1 ก้าวกระโดดครั้งเดียว** | 1,000 → 3,000 (+0.0240) หลังจากนั้นแกว่งในช่วง 0.853–0.868 |
| **Precision คือส่วนที่ได้ประโยชน์** | 0.7752 → 0.8285 (1,000 → 3,000) ส่วน Recall นิ่งที่ ~0.90 ตลอด |
| **14,000 ดีขึ้นเล็กน้อย** | F1 +0.0150 แต่ยังอยู่ในช่วงความแปรปรวนของการสุ่ม (ไม่ใช่แนวโน้มขาขึ้นชัดเจน) |

### ตีความ
- **10,000 แถวที่ใช้อยู่ปัจจุบัน (`NORMAL_COUNT = 10_000`) เพียงพอแล้ว** — เกินจุด plateau มาก
- ถ้าต้องการประหยัดเวลาเทรน ลดเหลือ **3,000–5,000 ก็ได้ผลใกล้เคียงกัน**
- **การเพิ่มข้อมูล synthetic ไม่ใช่ทางที่จะทำให้ระบบแม่นขึ้น** — bottleneck อยู่ที่อื่น

## 5. ⚠️ ข้อจำกัดสำคัญ (ต้องเขียนในเล่ม)

> **ข้อมูลที่ใช้เป็น synthetic** (สร้างจาก `generate_data.py`)

Learning curve นี้ตอบว่า *"ต้องใช้กี่แถวเพื่อเรียนรู้การกระจายตัวแบบสังเคราะห์ได้ครบ"*
**ไม่ใช่** *"ระบบแม่นยำกับ traffic จริงแค่ไหน"*

การที่ค่านิ่งเร็ว (3,000) ส่วนหนึ่งเป็นเพราะ **synthetic data มาจากการกระจายตัวคงที่**
— เพิ่มตัวอย่างจากการกระจายตัวเดิมย่อมไม่เพิ่มข้อมูลใหม่

**ตัวเลขความแม่นยำจริงต้องดูจาก:**
| รายงาน | วัดอะไร |
|---|---|
| `ml_real_eval_2026-07-22.md` | FPR บน traffic จริง = **14.0%** |
| `attack_set_eval_2026-07-22.md` | Recall แยกตาม attacker model (naive/VPN **100%**, targeted **8.7%**) |

## 6. สรุปสำหรับ thesis

> "เพื่อตรวจสอบว่าขนาดชุดข้อมูลฝึกเพียงพอหรือไม่ งานวิจัยนี้ทำการทดลอง learning curve
> โดยฝึกแบบจำลอง Isolation Forest ด้วยจำนวนตัวอย่างปกติที่เพิ่มขึ้นตามลำดับ
> (1,000 · 3,000 · 5,000 · 7,000 · 10,000 · 14,000) และประเมินบนชุดทดสอบเดียวกันตลอด
> (ปกติ 4,000 · ผิดปกติ 400) โดยเฉลี่ยผลจากการสุ่ม 3 รอบต่อขนาด
>
> ผลการทดลองพบว่าค่า ROC-AUC มีเสถียรภาพสูงตั้งแต่ตัวอย่างจำนวน 1,000 รายการ
> (0.9901–0.9912 ตลอดช่วง) ส่วนค่า F1 เพิ่มขึ้นอย่างมีนัยสำคัญเพียงครั้งเดียวในช่วง
> 1,000 → 3,000 (+0.0240) หลังจากนั้นเข้าสู่ภาวะคงที่ (plateau) โดยมีการเปลี่ยนแปลง
> น้อยกว่า 0.01 จึงสรุปได้ว่า **ชุดข้อมูลขนาดประมาณ 3,000 รายการเพียงพอ** สำหรับการ
> เรียนรู้การกระจายตัวของพฤติกรรมปกติ และขนาด 10,000 รายการที่ระบบใช้อยู่นั้นเกินพอ
>
> อย่างไรก็ตาม ข้อมูลที่ใช้ในการทดลองนี้เป็นข้อมูลสังเคราะห์ ผลลัพธ์จึงสะท้อนความ
> เพียงพอต่อการเรียนรู้การกระจายตัวสังเคราะห์เท่านั้น ข้อจำกัดที่แท้จริงของระบบไม่ได้
> อยู่ที่จำนวนตัวอย่าง แต่อยู่ที่การขาดข้อมูลการโจมตีจริงที่มีป้ายกำกับ ซึ่งได้แก้ไข
> ด้วยวิธี attacker modeling ในบทถัดไป"

## 7. ข้อเสนอแนะ

| ประเด็น | ข้อเสนอ |
|---|---|
| ลดเวลาเทรน | ลด `NORMAL_COUNT` เหลือ 5,000 ได้ (ผลเท่าเดิม เทรนเร็วขึ้น) — **แต่ไม่จำเป็นต้องทำ** |
| เพิ่มความแม่นยำจริง | ❌ อย่าเพิ่ม synthetic — ✅ เก็บ **real labeled data** แทน (bottleneck ที่แท้จริง) |
| ต่อยอด | ทำ learning curve บน **real normal** เมื่อมีข้อมูลมากพอ (ตอนนี้มี 700 sessions) |
