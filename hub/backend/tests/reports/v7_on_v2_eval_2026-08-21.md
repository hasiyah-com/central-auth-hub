## 3. 🔍 สาเหตุที่แท้จริง — bug ใน generator ของ V7

### หลักฐานที่ 1: FP ถูกขับด้วยฟีเจอร์เดียว

เทียบค่า sequence feature ระหว่าง normal ที่ถูก flag (73) กับที่ไม่ถูก flag (117):

| feature | ถูก flag | ไม่ถูก flag |
|---|---|---|
| **`success_sum`** | **1.178** | **0.000** |
| `rapid_gap_count` | 1.301 | 0.786 |
| `duration_log_range` | 3.285 | 2.703 |
| `concurrent_sum` | 0.068 | 0.017 |
| `subsystem_switch_rate` | 0.082 | 0.097 |

**normal ที่ไม่ถูก flag มี `success_sum = 0.000` พอดีทุกตัว** — ตัวแยกที่คมผิดปกติ

### หลักฐานที่ 2: ในข้อมูลเทรนของ V7 ค่านี้ไม่เคยเป็นอย่างอื่น

`scripts/run_feature_contract_v2.py`:

```python
@dataclass
class Event:
    failed_1h: int = 0
    success_10m: int = 0        # <- default
    concurrent_sessions: int = 0

def generate_normal(...):
    rows.append(Event(
        ...,
        failed_1h=failed,               # ✅ ส่งค่าเข้าไป
        concurrent_sessions=concurrent, # ✅ ส่งค่าเข้าไป
        active_subsystems=active_subsystems,
    ))                                  # ❌ ไม่เคยส่ง success_10m

# ฝั่ง attack เท่านั้นที่ตั้งค่า
elif attack == "attack_login_velocity":
    row.success_10m = 5
```

→ ในชุดเทรนทั้งหมด: **normal มี `success_10m = 0` ทุกแถว 100%** และ **attack เท่านั้นที่ > 0**

### ผลที่ตามมา

โมเดลเรียนกฎว่า **`success_10m > 0 ⟹ attack`** ซึ่งเป็นความสัมพันธ์ที่**สมบูรณ์แบบในข้อมูลจำลอง
แต่เป็นของปลอม** (generator artifact — ฟีเจอร์นี้ทำหน้าที่เป็น one-hot ของ attack type)

- อธิบายได้ว่าทำไม V7 ได้ recall 90.9% บนข้อมูลตัวเอง → แยกได้ง่ายเกินจริง
- อธิบายได้ว่าทำไมพังบนชุด V2 → ผู้ใช้จริง**ล็อกอินซ้ำใน 10 นาทีเป็นเรื่องปกติ**
- `login_velocity` / `concurrent_sessions` / `combined_ato` ได้ 100% เพราะตรง shortcut นี้พอดี
- `failed_spike` ได้แค่ 20.8% เพราะ `failed_1h` **ถูกส่งค่าให้ normal ด้วย** → ไม่มี shortcut

### หลักฐานที่ 3: FP กระจุกที่ผู้ใช้ที่ล็อกอินถี่

| ผู้ใช้ | FP rate | λ (login/วัน) | จำนวนช่วงเวลาหลัก |
|---|---|---|---|
| U04 | **79%** | 2.2 | 2 |
| U08 | **65%** | 3.3 | 2 |
| U10 | 56% | 2.6 | 2 |
| U11 | 18% | 2.8 | 2 (ดึก แคบ) |
| U03 | **0%** | 2.0 | 2 |
| U12 | **0%** | 2.5 | **3** (กระจายทั้งวัน) |

U12 λ ไม่ต่ำ แต่ FP = 0% เพราะล็อกอินกระจาย 3 ช่วง → ไม่ค่อยมีคู่ที่ห่างกัน < 10 นาที
สอดคล้องกับสาเหตุที่วินิจฉัยไว้

| 2 | **เทรน V7 ใหม่** หลังแก้ข้อ 1 แล้ววัดผลใหม่ทั้งของตัวเองและบนชุด V2 | `export_shadow_bundle_v7.py` |
| 3 | **เพิ่ม test กัน generator artifact** — ยืนยันว่าทุกฟีเจอร์เชิงตัวเลขมีค่า > 0 ในทั้ง normal และ attack (ไม่มีตัวไหนเป็นตัวแยกสมบูรณ์) | `tests/` |
| 4 | ตรวจ `concurrent_sessions` ด้วยเกณฑ์เดียวกัน — ค่าใน normal เกือบ 0 หมด (0.017) อาจมีปัญหาคล้ายกัน | `run_feature_contract_v2.py` |
| 5 | **ห้ามเปิด enforcement** จนกว่าจะแก้ข้อ 1–2 และรัน replay ผ่าน | — |

> ข้อ 3 สำคัญ: นี่คือด่านเดียวกับที่ `model_manifest` เป็นด่านจับไฟล์เสีย —
> ตัวเลขสวยบนข้อมูลตัวเองไม่ได้แปลว่าโมเดลดี ถ้าข้อมูลนั้นแยกง่ายเกินจริง
